# OpenClaw — VK Workspace

Канал [OpenClaw](https://github.com/openclaw/openclaw) для **VK Workspaces / VK Teams**. Бот получает сообщения через long polling и передаёт их агенту OpenClaw. Для подключения нужны **URL Bot API и токен бота**; публичный webhook и входящий порт не требуются.

Это интеграция корпоративного VK Teams, а не социальной сети «ВКонтакте». Для последней есть [openclaw-vk](https://github.com/pfrankov/openclaw-vk).

## Возможности и совместимость

Личные и групповые диалоги, несколько ботов, одобрение личного доступа через pairing, списки разрешённых пользователей и групп, проверка упоминания. Поддерживаются ответы на сообщения, форматирование Markdown, длинный текст без обрезания, кнопки с callback-действиями, редактирование сообщений бота, индикатор набора, отправка файлов и нативных голосовых, повторная отправка по `fileId` и приём файлов, изображений, голосовых и стикеров. Содержимое вложений обрабатывает OpenClaw при наличии нужных моделей.

Обычные ответы в личном диалоге отправляются без цитаты. В групповой беседе бот цитирует входящее сообщение, а ответы на callback-кнопки сохраняют привязку к сообщению с кнопкой.

Курсор и очередь событий сохраняются на диск. После перезапуска необработанные события остаются в очереди. Неудачные и прерванные ходы сохраняются для разбора, но не запускаются автоматически повторно.

**Целевая версия: OpenClaw `2026.9.3`, Node.js `24.16–24.x` или `26.1+`.** Это тот же диапазон, который объявляет OpenClaw 2026.9.3; Node.js 25 не поддерживается. CI проверяет Node.js 24 и 26. Перед переходом на другую версию OpenClaw проверьте совместимость SDK. У пакета нет сторонних runtime-зависимостей, кроме самого OpenClaw.

## Установка

Сначала настройте OpenClaw и выбранного агента: канал не создаёт модель и не заменяет её API-ключи.

### Из npm

```bash
openclaw plugins install @openclaw-vk/vk-workspace
openclaw plugins enable vk-workspace
```

Пакет публикуется в существующей организации [`openclaw-vk`](https://www.npmjs.com/org/openclaw-vk) через Trusted Publishing GitHub Actions. Для публикации используются короткоживущие OIDC-учётные данные и provenance; постоянный `NPM_TOKEN` не хранится. [GitHub Releases](https://github.com/pfrankov/openclaw-vk-workspace/releases) содержат заметки о версиях, а распространяемый пакет хранится только в npm.

## Подключение бота

Создайте бота в Metabot на вашем сервере VK Teams и получите токен. URL Bot API уточните у администратора: он может отличаться от адреса веб-клиента. Облачный адрес по умолчанию — `https://api.internal.myteam.mail.ru/bot/v1`, как в рабочем n8n-коннекторе.

Добавьте настройки в существующий `~/.openclaw/openclaw.json` или конфигурацию выбранного профиля:

```json
{
  "plugins": {
    "allow": ["vk-workspace"],
    "entries": { "vk-workspace": { "enabled": true } }
  },
  "channels": {
    "vk-workspace": {
      "enabled": true,
      "baseUrl": "https://teams.example.com/bot/v1",
      "botToken": "YOUR_BOT_TOKEN",
      "dmPolicy": "pairing"
    }
  },
  "session": { "dmScope": "per-account-channel-peer" }
}
```

**Не заменяйте весь конфиг этим примером.** Сохраните настройки моделей, агентов и других каналов; добавьте `vk-workspace` в существующий `plugins.allow`.

`baseUrl` принимает адрес сервера или полный endpoint `/bot/v1`. Суффикс добавляется один раз, префикс reverse proxy сохраняется. Логин, пароль, токен, query и fragment в URL запрещены.

```bash
openclaw gateway restart
openclaw channels status --probe
```

Probe проверяет `/self/get`. Активное соединение отмечается только после успешного `/events/get`, а не при самом запуске процесса. `pollTime` задаёт длительность long polling: по умолчанию 30 секунд, диапазон 1–60. `requestTimeoutMs` задаёт тайм-аут обычного запроса: по умолчанию 30000 мс. Для long polling тайм-аут автоматически составляет не меньше `pollTime + 10` секунд.

### Хранение токена

Вместо `botToken` можно использовать файл:

```json
{
  "channels": {
    "vk-workspace": {
      "baseUrl": "https://teams.example.com/bot/v1",
      "tokenFile": "/absolute/path/to/vk-workspace.token"
    }
  }
}
```

В файле должен быть только токен. Укажите абсолютный путь и ограничьте доступ пользователем Gateway; на Linux/macOS — `chmod 600`. Пустой или недоступный файл считается ошибкой. Одновременно задавать `botToken` и `tokenFile` нельзя.

Неявный аккаунт `default` также читает `VK_WORKSPACE_BOT_TOKEN` и `VK_WORKSPACE_BASE_URL`. Эти переменные должны быть доступны процессу Gateway, а не только терминалу. Явные настройки имеют приоритет; ошибочный `tokenFile` не подменяется токеном из окружения.

## Личные диалоги и pairing

Напишите боту. Неизвестный пользователь получит код; до одобрения его сообщение не передаётся агенту. На машине с OpenClaw:

```bash
openclaw pairing list vk-workspace
openclaw pairing approve vk-workspace <code>
```

После одобрения отправьте сообщение повторно. Ответ с кодом показывает ваш `userId`: сохраняйте его полностью, включая `@`, домен и другие символы.

Для доступа без pairing задайте `dmPolicy: "allowlist"` и `allowFrom: ["user@example.com"]`. Режим `"disabled"` отключает личные диалоги. Режим `"open"` открывает доступ всем и не рекомендуется для рабочего агента с инструментами.

Если `session.dmScope` отсутствует, канал выбирает `per-account-channel-peer`: разные пользователи и аккаунты не делят один личный диалог. Явная настройка OpenClaw имеет приоритет.

## Групповые чаты

Добавьте бота в чат и разрешите **и чат, и отправителей**:

```json
{
  "channels": {
    "vk-workspace": {
      "baseUrl": "https://teams.example.com/bot/v1",
      "tokenFile": "/absolute/path/to/vk-workspace.token",
      "groupPolicy": "allowlist",
      "groupAllowFrom": ["user@example.com"],
      "groups": {
        "123456@chat.agent": { "requireMention": true }
      }
    }
  }
}
```

Идентификатор чата берётся из `payload.chat.chatId` Bot API, не из названия. `groupAllowFrom` содержит пользователей, не чаты. **Одобрение личного pairing не даёт доступа в группы.**

По умолчанию бот реагирует на нативное упоминание, ответ на своё сообщение или mention pattern, настроенный в OpenClaw. Для группы можно задать `allowFrom`, `requireMention`, `enabled` и `systemPrompt`. Групповой `allowFrom` заменяет общий список отправителей. Правило `groups["*"]` применяется ко всем группам; `enabled: false` запрещает конкретный чат.

`groupPolicy: "disabled"` отключает группы. Режим `"open"` допускает любые группы и участников, сохраняя проверку упоминания. Управляющие команды проходят отдельную авторизацию OpenClaw: открытый чат сам по себе не даёт административных прав.

## Несколько ботов

```json
{
  "channels": {
    "vk-workspace": {
      "defaultAccount": "office",
      "dmPolicy": "pairing",
      "accounts": {
        "office": {
          "baseUrl": "https://teams.example.com/bot/v1",
          "tokenFile": "/run/secrets/office.token"
        },
        "support": {
          "baseUrl": "https://support.example.com/proxy/bot/v1",
          "tokenFile": "/run/secrets/support.token"
        }
      }
    }
  }
}
```

Аккаунты наследуют общие политики и URL, но **не чужие токены**. `VK_WORKSPACE_BOT_TOKEN` не используется именованными аккаунтами или явно созданным `accounts.default`. Идентификатор аккаунта содержит до 64 строчных латинских букв, цифр, `_` и `-` и начинается с буквы или цифры.

Для выбора агента используйте стандартные bindings OpenClaw с `channel: "vk-workspace"` и нужным `accountId`. Корневое `enabled: false` отключает весь канал, `accounts.<id>.enabled: false` — только выбранного бота.

## Форматирование, кнопки и голосовые

### Форматирование

По умолчанию `textFormat: "markdown"` преобразует поддерживаемую часть Markdown в HTML VK Teams: **жирный**, *курсив*, зачёркивание, ссылки HTTP(S), заголовки, inline-код и fenced code blocks. Исходный HTML экранируется. Таблицы и другие неподдерживаемые конструкции остаются обычным текстом. Это не полный CommonMark-парсер.

Теги и HTML-сущности не разрываются между сообщениями; каждая часть корректна сама по себе. Используются консервативные лимиты: 4096 UTF-16 единиц для текста, 1024 для подписи, включая разметку. Один исходный текст ограничен 1 МиБ. Для сервера без совместимого HTML-парсера задайте `textFormat: "plain"` в настройках канала или аккаунта — текст сохранится буквально, без `parseMode`.

### Кнопки

Канал расширяет стандартный инструмент OpenClaw `message`. Пример **аргументов инструмента**, а не команды терминала:

```json
{
  "action": "send",
  "channel": "vk-workspace",
  "target": "user@example.com",
  "message": "Продолжить разбор?",
  "vkButtons": [[
    { "text": "Продолжить", "callbackData": "Продолжить разбор", "style": "primary" },
    { "text": "Документация", "url": "https://teams.vk.com/botapi/" }
  ]]
}
```

У кнопки должно быть ровно одно поле: `url` или `callbackData`. Стили: `base`, `primary`, `attention`. Лимиты плагина: 10 рядов по 8 кнопок, 128 UTF-16 единиц в подписи, 256 UTF-8 байт в действии. Кнопки размещаются под последней частью ответа.

На сервер уходит случайный идентификатор, а не команда. Соответствие действию хранится локально и связано с конкретными ботом, аккаунтом, чатом и сообщением. Меню в ответе на входящее сообщение также привязано к его отправителю. Для самостоятельной отправки без контекста пользователя меню доступно только тем, кому разрешено общение с ботом политиками доступа.

Нажатие проверяет pairing, списки отправителей и права на управляющие команды; оно считается явным обращением к боту, но не обходит ограничения группы. Одно принятое нажатие погашает **всё меню**; остальные кнопки могут оставаться видимыми, но повторный запуск невозможен. Меню действует 24 часа. Если callback потреблён, а ход прерван, проверьте выполненные действия и отправьте новое меню. **Кнопки не являются механизмом подтверждения привилегированных инструментов OpenClaw.**

Для внутренних reply payload используется `channelData["vk-workspace"]` с полями `buttons`, `fileId`, `voice`, `textFormat`. `buttonOwnerId` — внутренняя ограничивающая привязка; вручную её задавать не требуется.

### Редактирование

```json
{
  "action": "edit",
  "channel": "vk-workspace",
  "target": "user@example.com",
  "messageId": "MESSAGE_ID_RETURNED_BY_SEND",
  "message": "**Готово.** Результат обновлён.",
  "vkButtons": []
}
```

Редактируются только текстовые сообщения, отправка которых зарегистрирована этим плагином. Чужой или неизвестный `messageId` отклоняется до HTTP-запроса. Из входящего хода редактирование ограничено его аккаунтом и чатом; ответ другому отправителю не редактируется без полномочий владельца. Хранятся последние 1000 записей на аккаунт, не старше 7 дней.

Если `vkButtons` не указан, меню сохраняется; `[]` удаляет его. Можно не передавать `message`, чтобы изменить только кнопки. Новый текст должен помещаться в одно сообщение: переполнение отклоняется, а не обрезается. Подписи файлов не редактируются. При неоднозначной ошибке редактирования старое меню погашается. Автоматического потокового обновления ответа на каждом токене нет.

### Голосовые и повторное использование файлов

```json
{
  "action": "send",
  "channel": "vk-workspace",
  "target": "user@example.com",
  "vkFileId": "EXISTING_VOICE_FILE_ID",
  "vkVoice": true,
  "message": "Голосовой ответ"
}
```

`vkFileId` позволяет использовать существующий `fileId` VK Teams без скачивания и загрузки. Не сочетайте его с `media`/URL вложения. Для нового файла передайте обычный `media` и `vkVoice: true`. Обычные файлы отправляются тем же способом без `vkVoice`.

Нативные голосовые: AAC, OGG, M4A, одно вложение на сообщение. Флаг reply payload `audioAsVoice` также поддерживается; возможности TTS объявлены OpenClaw. Плагин не транскодирует звук: MP3 и другие неподдерживаемые контейнеры отправляются обычным файлом. `forceDocument` принудительно выбирает обычный файл. Текст к голосовому отправляется отдельным сообщением, без потери подписи.

## Вложения и безопасность сети

`mediaMaxMb` ограничивает каждый файл: по умолчанию 20 МБ, максимум 100 МБ. Поддерживается до 10 вложений в сообщении; суммарно исходящие файлы ограничены 100 МБ и проверяются до начала отправки. Локальные исходящие файлы доступны только внутри media roots, предоставленных OpenClaw; выход через `../` или внешнюю символическую ссылку запрещён.

Входящие файлы скачиваются с origin Bot API и явно доверенных `mediaAllowedOrigins`. Если `/files/getInfo` возвращает другой файловый сервер, добавьте точный origin без пути и конечного `/`:

```json
{ "mediaAllowedOrigins": ["https://files.example.com"] }
```

Каждое перенаправление проверяется повторно. Токен бота не добавляется к скачиванию; подписанные URL не передаются модели. Другие публичные URL исходящих вложений обрабатываются через SSRF-защиту OpenClaw. Не добавляйте произвольные внутренние сервисы в доверенные origins.

По умолчанию требуется HTTPS. Для внутреннего центра сертификации настройте `NODE_EXTRA_CA_CERTS` у процесса Gateway, не отключая TLS-проверку. `allowInsecureHttp: true` разрешает HTTP как явное исключение: токен и сообщения тогда не шифруются.

Bot API передаёт токен и текст в query. Плагин не пишет полные URL и сырые ошибки API в логи, но **на сервере и reverse proxy также нужно скрывать query в access-логах**. Один токен нельзя одновременно использовать здесь и в другом long-poll потребителе, включая n8n: потребители могут забирать события друг у друга.

## Очередь и восстановление

Пакет событий сначала записывается в `<каталог состояния OpenClaw>/vk-workspace/<hash>.json`, затем следующий опрос подтверждает курсор. Каталог состояния учитывает `OPENCLAW_STATE_DIR`; обычное расположение — `~/.openclaw`. На POSIX каталог создаётся с правами `0700`, файлы — `0600`. Очередь содержит переписку, но не токен; защищайте её резервные копии.

Сообщения одного чата обрабатываются последовательно, одновременно — до четырёх чатов. Перед обработкой сохраняется отметка начала. Любая ошибка хода переводит событие в `failed` после первой попытки. Прерванный ход при следующем открытии очереди также попадает в `failed`. Более новые сообщения этого чата ожидают решения оператора; остальные чаты продолжают работать. Лимиты — 1000 событий суммарно и 16 МБ файла. При заполнении опрос прекращается без подтверждения несохранённого пакета.

Для обслуживания используйте checkout проекта и сначала остановите канал:

```bash
node scripts/inbox.mjs status /absolute/path/to/inbox.json
node scripts/inbox.mjs retry /absolute/path/to/inbox.json
# Удалить конкретное failed-событие БЕЗ повторного выполнения (осознанно):
node scripts/inbox.mjs discard /absolute/path/to/inbox.json EVENT_ID
```

`status` не печатает тексты сообщений, `retry` возвращает неудачные события в очередь, `discard` удаляет только указанное failed-событие и не меняет курсор. Повторный запуск после `retry` может повторить инструменты: сначала проверьте разговор и внешние изменения. После аварийного завершения может остаться `.lock`: остановите всех потребителей этого бота и удалите только соответствующий `.lock`, не JSON. Автоматический захват чужой или устаревшей блокировки запрещён. Повреждённый JSON восстановите из резервной копии, не сбрасывайте курсор.

**Доставка не является exactly-once.** Плагин не перезапускает неоднозначно завершившиеся ходы автоматически. Сбой после отправки ответа или частичного выполнения хода всё равно требует сверки результата; повтор вручную или средствами очереди самого OpenClaw может повторить ответ либо действие инструмента. Перед ручным `retry` проверьте уже выполненные действия. Внешние операции агента должны иметь собственную идемпотентность или подтверждение.

Состояние собственных сообщений и меню хранится отдельно в `<hash>.messages.json`, включает текст и действия кнопок и тоже требует защиты. Не путайте этот файл с входящей очередью. Перед удалением оставшейся `.messages.json.lock` остановите все операции канала. POSIX-запись синхронизирует файл и каталог после rename; на Windows Node.js не предоставляет переносимого fsync каталога.

## Ограничения

Агента запускают новые сообщения и разрешённые нажатия на меню плагина, но не редактирования, удаления, реакции или ветки обсуждений. Административные операции с чатами и участниками не предоставляются. Отказ индикатора набора или подтверждения callback не повторяет агентный ход. Временная ошибка `/self/get` при старте вызывает отменяемое ожидание и повторное подключение, а не завершение аккаунта.

Локальные HTTP-тесты и проверка настоящего SDK не заменяют подключение к вашему VK Teams. При внедрении проверьте корпоративный proxy, TLS, права бота и origin файлового сервера.

## Разработка и релизы

```bash
npm ci --ignore-scripts
npm run check          # тесты, синтаксис, сборка и проверка настоящего npm-архива
npm run test:coverage
npm run install:host   # изолированная установка закреплённого OpenClaw
npm run check:host     # загрузка архива и проверка контрактов настоящего SDK
```

`src/` содержит код, `test/` — тесты, `scripts/` — сборку, проверки и обслуживание очереди. Пользовательские действия и ожидаемые результаты собраны в [docs/scenarios.md](docs/scenarios.md), правила изменений — в [AGENTS.md](AGENTS.md).

CI запускается на PR и изменениях `main`. Для релиза обновите версии в `package.json`, `package-lock.json`, `openclaw.plugin.json` и [CHANGELOG.md](CHANGELOG.md). После проверок и merge создайте тег на проверенном коммите `main`:

```bash
git tag v0.1.4
git push origin v0.1.4
```

Workflow проверяет принадлежность коммита `main`, совпадение версий и CHANGELOG, повторяет тесты и SDK-проверку, публикует пакет в npm через Trusted Publishing и создаёт GitHub Release с заметками из CHANGELOG. npm добавляет provenance автоматически. Actions закреплены полными SHA; существующие npm-версии и GitHub Releases не перезаписываются. Токен VK Teams и постоянный `NPM_TOKEN` не нужны.

## Источники и лицензия

Рабочий HTTP-контракт: [n8n-nodes-vk-teams](https://github.com/pfrankov/n8n-nodes-vk-teams) и его [OpenAPI subset](https://github.com/pfrankov/n8n-nodes-vk-teams/blob/master/docs/vk-teams-bot-api.openapi.yaml). `ok: false` считается ошибкой даже при HTTP 200; файлы отправляются multipart POST, остальные параметры — query. Ответы на сообщения и индикатор набора сверены с [официальным Python SDK](https://github.com/mail-ru-im/bot-python/blob/master/bot/bot.py).

Дополнительный справочник возможностей: [belka-tech/php-vk-teams-bot](https://github.com/belka-tech/php-vk-teams-bot). Код PHP не включён в пакет. При расхождении параметров приоритет у проверенного n8n-контракта: callback использует `text`, а удаление сообщений — повторяющиеся `msgId`, не JSON `msgIds`.

Дополнительно: [VK Teams Bot API](https://teams.vk.com/botapi/?lang=ru), [SDK каналов OpenClaw](https://docs.openclaw.ai/plugins/sdk-channel-plugins), [пример канала VK](https://github.com/pfrankov/openclaw-vk).
